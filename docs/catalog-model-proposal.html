Catalog items, contents, characters and relationships

October 19, 2026 · Design history — unified contents implemented; see implementation and verification for current behavior

The distinction

ConceptMeaningExample
Catalog itemA particular retail release with its own identity, year, market, packaging and expected contents.A Snow Job single-card release or a multipack.
Content / partA physical component that can be present, missing or owned separately. Retains expected quantity, image and optional parent grouping.Figure, driver, ski, rifle, vehicle, box or file card.
CharacterThe identity represented by a component. Character names do not carry ownership or quantities independently.Snow Job on a figure component; a driver character on a vehicle driver component.
Related catalog itemAnother release associated through a variant, repaint, international, packaging or general relationship.A repaint of the same release. This does not mean it is included in the box.

Proposed editing flow

  1. Enter release metadata.
  2. Use one Contents section to add figures, vehicles, gear, packaging and paperwork. Each row has name, quantity and images. Figure/driver rows additionally offer Character; zero or several character identities remain possible when a component represents more than one.
  3. For a single figure, prefill one primary figure component with quantity 1. Entering its character happens on that row. A vehicle can contain its primary vehicle and an optional driver; multipacks use multiple figure/vehicle rows. Do not require a separate catalog entry for every included driver or accessory.
  4. Show a derived Characters summary for searching and browsing. Avoid asking the administrator to enter the same character in a separate section. Existing character associations without a part remain preserved and flagged for association during later editing, rather than silently discarded.
  5. Keep Related Releases separate for variants and other release relationships. Rename the action to Add Related Release and show a name/year thumbnail picker rather than raw IDs.

Character identities are shared across different releases; that does not make their physical figures interchangeable.

Two different kinds of link

A link from a content row to another catalog entry is a reference describing that included component. A link in Related Releases connects entire retail releases. They must use different controls and descriptions.

For the first iteration, keep content references explicit and optional. A reference to a single-card figure must not imply its packaging, weapons or paperwork are included in a multipack. The source item's own content rows remain the authority for what is included. Link only a verified matching component; visual resemblance or a shared character is insufficient.

If later we need automatic reuse of component names/images across releases, introduce reusable component definitions separately from retail releases. A shared part definition could serve several releases while each release retains its own expected quantities. Do not make every weapon or driver a standalone retail catalog item just to enable reuse.

Collection behavior

Owning a multipack records quantities against that multipack's contents. It does not silently create separately owned catalog copies for each linked figure. Likewise, a related-release link never implies ownership.

Snow Job example: Figure 0, Skis 2, Rifle 0, other contents 0 or unknown according to what the collector actually knows. Keep accessory ownership distinct from confirmed ownership of the primary toy. Multiple physical copies still have separate collection entries and their own quantities/conditions.

Nested parts group contents; quantities remain absolute per retail release. Never multiply them implicitly. Choosing a shared reference must not introduce recursive contents, cycles, duplicate inventory, or duplicate valuation.

Decisions for the next design discussion

  • Start with one Contents editor and derived character summary, or also build a reusable component library now? Recommendation: the Contents editor first; add shared definitions only when real reuse warrants them.
  • Should linking a reference offer to copy selected content rows once? Recommendation: defer automatic copying initially; later make it an explicit, previewed action, with no ongoing synchronization surprises.
  • Should individual components have their own public detail pages? Recommendation: expandable contents within their release initially, with optional links to existing exact catalog records.

No schema, ownership calculation, relationship behavior or catalog content has been changed by this proposal.

Refinement: everything physical is a part

Following the collector's proposal, use one part model for every physical component of a catalog item. A figure release, vehicle, playset or multipack can each have zero or many parts. Part type describes what it is: Figure, Vehicle, Accessory, Other Part, Packaging or Paperwork. Other Part covers structural components such as wheels or doors without classifying an entire wheel as a vehicle.

Keep type independent from role. A separate Main Component flag preserves ownership meaning: a vehicle and its driver can have types Vehicle and Figure respectively, while only the vehicle is designated as a main component of that vehicle release. Included figures/vehicles in a multipack may each be main components. Existing primary/accessory/packaging/paperwork kinds currently encode role; they cannot be relabeled into physical types without separating these dimensions.

Each part retains name, expected quantity, images, optional parent and character associations. Snow Job: figure type Figure, main component yes, quantity 1; skis type Accessory, quantity 2; rifle type Accessory, quantity 1; packaging and file card have their own rows. The character is attached to the figure, not repeated as separate ownership. A catalog item with no verified parts can be saved but does not support inferred completeness.

Primary status continues to distinguish main-toy ownership from parts-only ownership. It does not imply the entire retail release is complete. Owning one main figure from a multipack means having part of the release, not having every figure. Completeness requires the complete expected contents and original packaging under the existing definition.

All physical quantities belong to the release's part rows. Parent links group them without multiplying quantities. Related Releases links connect variants/repaints; optional part references identify matching content elsewhere. Neither creates a new owned copy or imports all of another release's contents automatically. This remains a design proposal; no part schema or collection rules have changed.

Current archive behavior

The Archived flag excludes the item from normal catalog browsing/search and prevents adding new collection copies. Administrator lists include retired items; existing collection copies remain editable, and direct catalog detail requests still work. This is catalog archiving, not a claim that Hasbro discontinued the product. The editor checkbox is now labeled Archived; its existing behavior is preserved.
