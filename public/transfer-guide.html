Version 1 file formats

Workflow and identifiers

Download a template, fill it out, choose CSV or JSON, then validate. The preview lists proposed additions/updates and row errors. Nothing is saved until you commit a valid preview. Previews expire in 30 minutes. Import 1–50 rows and at most 2 MB at a time; large nested parts lists may require smaller files.

A blank or missing item ID creates a new record with a generated stable ID. An existing ID updates that record. Collection updates are restricted to your collection. Each copy is a separate row, even when its release ID matches another row. Reusing a committed preview does not create duplicate copies. Re-previewing a file with blank IDs intentionally creates new copies.

Updates replace submitted data fields. Start from an export when editing existing records so you keep private facts and part details. Omitted or retired catalog parts retain historical owned quantities. A catalog update requires its current expectedRevision; stale changes must be revalidated. Catalog imports use the same rules as the catalog editor.

JSON

{
  "version": 1,
  "kind": "collection",
  "items": [{
    "name": "Unidentified accessory",
    "condition": "Unknown",
    "completeness": "Not sure",
    "packaging": "unknown",
    "sealed": null,
    "unidentifiedParts": [{"name": "Helmet", "quantity": null}]
  }]
}

For catalog files, use "kind": "catalog" in the envelope. Each catalog item has its own kind: figure, vehicle, playset, accessory, multipack, or other. Downloads provide every supported field. Unknown fields are rejected to catch mistakes.

CSV

The first row is a header. Every data row includes schemaVersion equal to 1 and transferKind equal to collection or catalog. Catalog item type uses the separate kind column. Quoted cells may contain commas, double quotes and newlines; double internal quotes as "".

Nested fields are JSON arrays inside CSV cells: parts, unidentifiedParts, fileCards, taxonomyIds, and related where applicable. Example cell contents before CSV quoting:

[{"partId":"stable-part-id","quantity":0,"condition":"Good","defects":"Discoloration"}]

Blank nullable scalar fields mean unknown or unset. Empty collection grade/completeness/packaging fields use defaults. Empty ownership allows classification from recorded primary parts. Export prefixes spreadsheet formula characters with an apostrophe; import removes that protective prefix to preserve the original text.

Collection fields

FieldsMeaning
id, releaseId, nameStable copy ID; optional reference release ID; display name.
ownershipowned, parts_only or unconfirmed. May be omitted for classification from quantities.
conditionMint, Excellent, Good, Fair, Poor or Unknown.
completeness, packaging, sealedComplete / Partial / Not sure; present / absent / unknown; true / false / null. Complete requires original packaging and every expected part; it does not imply sealed or Mint.
partsObjects with partId, quantity, optional condition and defects. Null means unknown; 0 means absent. Expected quantities are absolute per release, never multiplied by parent parts.
unidentifiedPartsObjects with name, quantity, optional condition and defects.
reviewedRevisionThe catalog revision reviewed for this copy, or null if review is needed.
notes, location, acquiredAt, purchasePriceCents, purchaseCurrency, purchaseSourcePrivate owner facts. Dates use a valid YYYY-MM-DD date. Prices are whole cents, with a three-letter uppercase currency code. These fields are never exported for another collector.

Catalog fields

The editor and templates support name, character, type, year, line, series, subSeries, wave, scale, faction, market, manufacturer, productCode, upc, retailPriceCents, retailCurrency and retired. parts contains stable id, name, kind (primary/accessory/packaging/paperwork), nullable expectedQuantity, nullable parentId, sortOrder, and optional linkedReleaseId. Component IDs must be unique; parent parts must belong to the same release and cannot form cycles.

fileCards contains stable id and plain text. taxonomyIds references existing terms created by the administrator. related contains release id and relationship kind: variant, repaint, international, packaging or related. These are links to separate catalog releases. New releases may reference other releases in the same import.

Retirement prevents new additions while preserving existing copies. Duplicate merging is a separate reviewed operation in catalog administration; importing does not guess a merge or infer matching parts.

Photos are separate

Upload photos through the item or catalog editor after importing. JSON exports include mediaMapping with stable entry/release/part/file-card IDs and authorized photo URLs. Photo bytes are not embedded in templates or CSV. Save photo files separately while signed in if you need an offline copy. A data export is not a full database/media backup.

JPG, PNG and WebP files up to 8 MB are accepted by the browser uploader. It resizes and converts them to JPEG; the server decodes and encodes fresh pixels, removing source metadata. API uploads must be processed JPEGs with at most 4 megapixels. Each collection copy allows ten photos. Collection photos stay private unless linked to a public collection viewed by another signed-in collector.
